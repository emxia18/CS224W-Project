# Synthetic Connections candidates

## Current batch: paper_v2

The closer implementation is in [`paper_v2/`](paper_v2/METHODS.md): 15
false-connection families and 15 intentional-overlap families, actual frozen
MPNet quartet scoring, 24 candidate variants per family, and separate editor and
difficulty-ranking agents. Labels are limited to four words. See
[`paper_v2/METHODS.md`](paper_v2/METHODS.md) for remaining departures and rerun
commands; this is not an exact reproduction of the original GPT-4 experiment.

Use [`paper_v2/puzzles.json`](paper_v2/puzzles.json) for one
candidate per retained family, [`paper_v2/variants.json`](paper_v2/variants.json)
for all retained difficulty variants, and
[`paper_v2/validation_report.json`](paper_v2/validation_report.json) for actual
counts and checks. These siblings share categories and should not be treated as
independently generated designs or split between training and evaluation.

## Original batch: editorial adaptation

First batch: eight puzzles generated by a Codex subagent, adapting the iterative
creator stage in Merino et al., [Making New Connections (2024)](https://arxiv.org/abs/2407.11240).

`puzzles.json` contains shuffled boards and answer keys. `generation_trace.json`
records inspiration seeds, candidate pools, and distractor relationships.
Four puzzles use a false connection: four apparent group members are distributed
across four actual answers. Four use intentional overlap: a word in an earlier
answer suggests a different meaning connecting a later answer.

This is an adaptation, not a full reproduction of the paper. The creator uses
eight-word candidate pools and selects quartets editorially. MPNet enumeration
of all 70 quartets per pool, the 24 difficulty assignments, independent LLM
editing, and human evaluation have not been performed. Colors are provisional.
Structural validity does not establish a unique semantic solution or fairness.
These are candidates for human review, not certified publishable puzzles.

Validate structure and check exact answer-group reuse against the local historical
dataset from the repository root:

```sh
python3 'data generation/validate.py'
```

The checker writes `validation_report.json`. Its historical comparison covers
only the local dataset; it cannot establish global novelty. The puzzles use the
project's `words` and `answers[].answerDescription/words` fields, with additional
synthetic metadata. They deliberately have no invented publication dates.
`prepare_data.py` expects exactly 652 dated historical puzzles, so this batch
must be loaded separately. Existing train/validation/test files are preserved.

Before using these for training, review group membership, alternative complete
partitions, distractor plausibility, and provisional colors. Keep generated
training data separate from historical validation/test evaluation.
